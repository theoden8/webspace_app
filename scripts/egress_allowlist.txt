# Egress allowlist for the Linux integration tier (INTEG-016).
#
# Every target the suite is permitted to contact off the runner. Loopback
# is not listed: the nftables ruleset returns on 127.0.0.0/8 and ::1
# before anything reaches the recorder, so fixture servers, the Dart VM
# service and the proxy relay never appear here.
#
# Format, one per line:
#   dns:<suffix>    a name the resolver may be asked for
#   host:<suffix>   a name in a TLS SNI or an HTTP Host header
#   ip:<addr|cidr>  a literal destination
# A suffix matches the name itself and everything under it, so
# `dns:example.org` covers `icons.example.org`.
#
# Every entry needs a comment saying which code path makes the request and
# why it may leave. An entry without one is an unreviewed row missing from
# the ip-leakage coverage matrix (LEAK-007), not a permission.
#
# One address is exempted in the ruleset rather than listed here: the
# `leak-origin` service container, resolved at arm time into
# WS_EGRESS_EXEMPT. It is not egress -- it sits on this job's own bridge
# network and never leaves the CI host -- but it cannot be loopback either,
# because proxy_fail_closed_test.dart needs a destination this job does not
# own (BUG-014 gap 2). Recording it would break that arm's controls.
#
# Deliberately empty. A hermetic suite contacts nothing: a test that needs
# a server should stand one up on loopback (see integration_test/
# fixture_server.dart), and a production path that reaches out during a
# test is the finding this gate exists to surface. Adding the first entry
# here should be an argued change, not a way to get CI green.
